# OpenEtruscan Development Guide

This guide covers setting up, developing, and testing the `openetruscan` Python core package and CLI.

*For web frontend and Next.js development, refer to [`openEtruscan-frontend`](https://github.com/Eddy1919/openEtruscan-frontend).*

---

## 1. Environment Setup

Clone the repository and install dependencies using `uv` (recommended) or standard `pip`:

```bash
git clone https://github.com/Eddy1919/openEtruscan.git
cd openEtruscan

# Recommended: locked environment via uv
uv sync --extra dev

# Alternative: standard pip editable install
pip install -e ".[dev]"

# Install pre-commit hooks
pre-commit install

# Run the test suite
pytest
```

---

## 2. Development Database

The test suite executes against three backends automatically:
1. `DATABASE_URL` if explicitly set (PostgreSQL + pgvector)
2. A temporary `testcontainers` PostgreSQL container if Docker is running
3. In-memory SQLite fallback (PostgreSQL-specific tests skip automatically)

To run tests against a persistent local PostgreSQL service:

```bash
docker compose -f docker-compose.dev.yml up -d db
DATABASE_URL=postgresql://openetruscan:openetruscan@localhost:5432/openetruscan pytest
```

---

## 3. Database Migrations

Schema migrations are managed by Alembic in `src/openetruscan/db/versions/`:

```bash
# Create a new migration
alembic revision --autogenerate -m "Add new column"

# Apply migrations
alembic upgrade head
```

CI runs `tests/test_migrations.py` to enforce two invariants:
- Migrations must apply cleanly to an empty database.
- All ORM models in `src/openetruscan/db/models.py` must match the schema generated by Alembic.

## 4. Model Training & Evaluation

Train neural classification heads (CharCNN, MicroTransformer, EmbeddingMLP) via the CLI:

```bash
# Train CharCNN on local split
openetruscan train-neural --arch charcnn --output data/models/

# Run inference
openetruscan predict-neural --arch charcnn "mi aviles"
```

For evaluation protocols, frozen test splits, and bootstrap metrics, see [`research/v2/`](../research/v2/) and [`docs/INTELLIGENCE_V2.md`](INTELLIGENCE_V2.md).

---

## 5. Local FastAPI Server (Parity Reference)

To start the local FastAPI server for development and testing:

```bash
uvicorn openetruscan.api.server:app --reload
```

If you modify API route signatures or schemas, update the committed OpenAPI specification:

```bash
python scripts/ops/generate_openapi.py
```

---

## 6. Continuous Integration & Quality Checks

Run all verification tools before pushing changes:

```bash
# Linting & Formatting
ruff check src/ tests/
ruff format --check src/ tests/

# Type Checking
mypy src/openetruscan/

# Release Manifest Invariant Check
uv run python scripts/ops/check_release_truth.py
```
