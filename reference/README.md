# Reference data

Small, versioned tables that `scripts/data_pipeline/build_edition_layer.py`
reads to fill the edition-layer tables (aliases, ET sigla and text classes,
findspots, current locations, coverage index). Every coordinate here comes
from a Pleiades dump and every cross-reference from Burman's concordance;
nothing is typed in by hand except the rows marked `manual`.

## How the tables are used

1. **Aliases.** Each record's own ID is read as a reference (`Ta 3.6` → ET,
   `CIE 4538` → CIE, a bare number → CIEP), then every Burman row that shares
   a reference with it adds the rest. Bare IDs are CIEP numbers (Hill 2018,
   via the Larth dataset); inside published CIE ranges the CIEP number is the
   CIE number, so those rows get a CIE alias with `basis=ciep_cie_numbering`,
   `confidence=probable`. It is raised to `high` when the record's text
   matches the record that carries that CIE number directly.
2. **ET text class.** Taken from the ET² siglum when Burman has one, else
   ET¹. Stored in `inscription_edition.rix_text_class`. The site's own
   `classification` column is left as it is.
3. **Findspot.** The findspot string decides first (`findspot_gazetteer.csv`).
   When it names no place, the ET region code decides (`et_regions.csv`).
   When a bare city name conflicts with a direct ET region, the region wins;
   an explicit find phrase (`in agro`, `repertum`) keeps the string's place.
   The precision sets `findspot_uncertainty_m`: site 1 km, city 3 km,
   territory 20 km, region 75 km.
4. **Current location.** Custody clauses (`in museo publico Clusino`,
   `nunc (1886) …`) go to `inscription_edition.current_location`. With
   `--clear-custody-findspots`, strings that are only custody or only an
   object description leave `findspot` and are kept verbatim in
   `findspot_source_text`, with a `provenance_audits` row each.
5. **Coverage index.** Burman rows that match no record go to
   `indexed_documents`: known inscriptions the corpus does not hold. The
   index stores references only, never text; REE texts stay with their
   publisher.

## Regenerating

```bash
# places.csv (needs the Pleiades dump)
curl -LO https://atlantides.org/downloads/pleiades/dumps/pleiades-places-latest.csv.gz
python scripts/data_pipeline/build_reference_places.py \
    --places pleiades-places-latest.csv.gz --out reference/places.csv

# findspot_gazetteer.csv (keeps basis=manual rows)
DATABASE_URL=… python scripts/data_pipeline/build_findspot_gazetteer.py --from-db

# frontend copies (lib/reference/*.json in openEtruscan-frontend)
python scripts/data_pipeline/export_reference_json.py \
    --out ../openEtruscan-frontend/lib/reference
```

To correct a findspot reading, edit its row in `findspot_gazetteer.csv` and
set `basis` to `manual`; regeneration will keep it. Re-running
`build_edition_layer.py` then attributes every record with that string to
the corrected place, and the same goes for an `et_regions.csv` fix.

The attribution lives in `inscription_edition` (`findspot_place`,
`findspot_precision`, `findspot_basis`). The script never writes
`inscriptions.findspot_lat`/`findspot_lon`, `findspot_uncertainty_m`,
`pleiades_id` or `geom`: those keep what the source recorded. A place's
point in `places.csv` is Pleiades' representative point for the whole
place, so copying it onto a record would pass a city or territory off as a
find position.

## Known limits

- The 33 secondary ET region codes need checking against Rix's
  introduction to ET (1991) before they count as scholarly.
- S, G and N are inferred, not read from Rix.
- Burman's concordance has rows where editors disagree on identity
  (column O, "Multiple references?"); a reference can therefore resolve to
  more than one record, and the API answers those with a candidate list.
